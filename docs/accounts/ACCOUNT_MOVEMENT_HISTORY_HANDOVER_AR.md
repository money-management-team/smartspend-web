# سجل حركات الحساب — SmartSpend

تاريخ التعديل: 2026-10-02.

هذا التعديل مبني على نسخة الفرونت التي تضم التسجيل الصوتي، حدود الصوت والفواتير، مراجعة المسودات، وحالة انتظار معالجة الصوت. يضيف سجل الحركات داخل صفحة تفاصيل الحساب `/dashboard/accounts/:accountId`.

## النطاق

التعديل في الفرونت فقط. الباك الحالي يوفر البيانات اللازمة؛ لا توجد تغييرات على Laravel أو قاعدة البيانات أو إعدادات Laravel Cloud، ولا توجد مكتبات جديدة.

يظهر السجل بعد بطاقة الرصيد وقبل معلومات الحساب، للحسابات النشطة والمؤرشفة. لا يغير هذا التعديل إنشاء العمليات أو اعتمادها أو عكسها أو تعديل الحساب أو أرشفته.

## عقد الربط مع الباك

يستخدم السجل `transactionsApi.list` الموجودة، عبر طلب مصادق عليه:

```http
GET /api/transactions?account_id=10&page=1&per_page=20&sort_by=occurred_at&sort_dir=desc
```

عند اختيار الفلاتر تُضاف فقط معاملات الباك الحالية: `type` و`status` و`date_from` و`date_to`. الخيارات الأخرى هي ترتيب التاريخ/وقت التسجيل، وحجم الصفحة 20 أو 50 أو 100. لا يُرسل `workspace_id` مصطنع؛ الباك يحدد نطاق مساحات العمل من الجلسة.

المسار المعتمد للاستجابة هو `response.data.transactions`. الحركات في `.data`، والصفحات من `total` و`current_page` و`last_page` و`per_page` و`from` و`to`. لا تنقل هذه البيانات إلى envelope جديد في الباك دون تحديث العميل والاختبارات.

يعتمد الباك على `whereHas('ledgerEntries', account_id)`، ويحمّل `ledgerEntries.account` و`category` و`creator`. لذلك يشمل السجل جميع العمليات التي لها قيد فعلي على الحساب، بما فيها تحويلات أهداف الادخار وحركات الديون والرسوم والعكس.

زر «تحديث السجل والرصيد» يقرأ السجل و`accountsApi.get(accountId)`، ويستخدم `current_balance` الذي يحسبه الباك. طلبات الصفحات والفلاتر تقرأ السجل فقط. لا توجد أي طلبات مالية كتابية في المكون الجديد.

## قواعد يجب الحفاظ عليها

1. **أثر الحركة يأتي من قيود الحساب نفسه.** لا تستخدم `transaction.amount` لتحديد مقدار الخصم أو الإضافة، ولا تحدد الاتجاه من نوع العملية وحده. التحويل نفسه يظهر صادرًا في حساب المصدر وواردًا في حساب الوجهة.
2. يجمع المكون جميع قيود الحساب داخل العملية الواحدة، بما فيها الرسوم، ويتيح فتح تفصيل كل قيد. قيود الحسابات الأخرى لا تدخل في المبلغ أو ملخص الصفحة.
3. تُعرض العملية الأصلية المعكوسة وقيد العكس كحركتين مستقلتين. لا تحذف الأصل من العرض أو من الحساب؛ كلاهما جزء من دفتر الأستاذ.
4. المبالغ القادمة من الباك سلاسل عشرية. الجمع يستخدم `BigInt` بوحدات ذات أربع منازل عشرية، والتنسيق يحافظ على الدقة حتى للمبالغ الكبيرة. لا تمررها إلى `Number` أو `parseFloat` قبل الجمع.
5. **إجمالي عدد العمليات يشمل كامل السجل المطابق للفلاتر.** مبالغ الوارد والصادر والصافي تخص الصفحة المعروضة فقط، وتسمياتها توضح ذلك. لا تعرضها كمجموع مالي لكامل السجل.
6. الرصيد الحالي أعلى الصفحة يأتي من الباك ويشمل الرصيد الافتتاحي وكامل القيود. لا تستنتج رصيدًا تراكميًا لكل حركة من صفحة جزئية.
7. التاريخ المستخدم في الفلترة مطابق لاستعلام الباك بتوقيت UTC. الأوقات المعروضة تستخدم منطقة المستخدم/مساحة العمل وفق منطق الصفحة الموجود.
8. عند تبديل الحساب أو الفلاتر تُلغى القراءة القديمة، وتُهمل استجاباتها المتأخرة. لا تسمح باستبدال سجل حساب بسجل حساب آخر.
9. تُتحقق هوية الحساب ومساحة العمل وعملة قيوده وهوية العملية قبل عرض السجل. الاستجابة غير المتوافقة تظهر خطأ بدل بيانات أو أصفار مختلقة.
10. تفاصيل المبالغ والحسابات والوصف تُعرض كنصوص وروابط React؛ لا تستخدم `dangerouslySetInnerHTML` لعرض بيانات المستخدم.

## المحتوى والتصميم

- جميع الأنواع الحالية: الدخل، المصروف، التحويل، الرسوم، الاسترداد، التسوية، العكس، استلام قرض، الإقراض، السداد والتحصيل.
- يوضح مصدر التسجيل، بما فيه التسجيل الصوتي والفاتورة والإدخال اليدوي والاستيراد والعمليات المتكررة.
- تفاصيل قابلة للفتح: التواريخ، التصنيف، المرجع، منشئ العملية، الوصف، سبب العكس وقيود الحساب.
- روابط لتفاصيل العملية والتحويل والدين والعملية الأصلية والحسابات المرتبطة عند وجود بياناتها.
- تحميل بهيكل مؤقت، خطأ مع إعادة المحاولة، سجل فارغ، نتائج تصفية فارغة، وصفحات قابلة للتنقل.
- يستعمل متغيرات التصميم الحالية، يدعم العربية والإنجليزية وRTL/LTR والوضع الداكن، ويتكيف مع الشاشات الصغيرة. يحترم `prefers-reduced-motion`.

## التركيب في VS Code / PowerShell

من جذر مشروع الفرونت، أنشئ الملفات الجديدة فقط عند عدم وجودها:

```powershell
$files = @(
    'src/features/Dashboards/User/AccountDetails/AccountMovementHistory.jsx',
    'src/features/Dashboards/User/AccountDetails/AccountMovementHistory.css',
    'src/features/Dashboards/User/AccountDetails/accountMovementHelpers.js',
    'src/features/Dashboards/User/AccountDetails/accountMovementMessages.js',
    'tests/accountMovements.test.mjs',
    'docs/accounts/ACCOUNT_MOVEMENT_HISTORY_HANDOVER_AR.md'
)
foreach ($file in $files) {
    New-Item -ItemType Directory -Path (Split-Path $file) -Force | Out-Null
    if (!(Test-Path $file)) {
        New-Item -ItemType File -Path $file | Out-Null
    }
}
```

ضع محتوى كل ملف مرفق كاملًا في مساره أعلاه. استبدل كذلك محتوى `AccountDetails.jsx` كاملًا بالملف المعدل. حافظ على حالة الأحرف في أسماء الملفات، لأن استضافة Linux تتعامل معها بدقة.

لا تحتاج إلى تعديل `package.json` أو `package-lock.json` أو ملفات ترجمة التطبيق العامة أو `AccountDetails.css`. ولا تحتاج إلى أوامر Composer أو migrations.

## التحقق

اختبار التعديل منفردًا:

```powershell
node --test tests/accountMovements.test.mjs
npm run build
```

اختبار التعديل مع ميزات الصوت والفواتير الموجودة:

```powershell
node --test tests/aiInputContracts.test.mjs tests/voiceRecording.test.mjs tests/voiceCaptureFlow.test.mjs tests/accountMovements.test.mjs
```

التحقق المنفذ أثناء إعداد التعديل: **18 اختبارًا جديدًا ناجحًا، و148 اختبارًا ناجحًا بالمجموع، وبناء إنتاج ناجح، وESLint ناجح للملفات البرمجية المعدلة والجديدة**. ظهر تحذير حجم الحزم الموجود في المشروع؛ لم يفشل البناء.

تعذر الفحص المرئي المحلي في المتصفح المتاح أثناء إعداد الملفات بسبب منع فتح عنوان localhost. لذلك يلزم تنفيذ فحص الواجهة أدناه على بيئة المستخدم؛ ولا تعتبر الاختبارات الآلية دليلًا على اكتمال فحص التصميم أو تجربة الربط الحية مع Laravel Cloud.

### فحص يدوي بعد التركيب

```powershell
npm run dev
```

1. افتح حسابًا لديك عليه عمليات. تأكد من ظهور سجله ومبالغ الحركات واتجاهاتها.
2. افتح تحويلًا في حساب المصدر والوجهة، وتحقق من أنه صادر في الأول ووارد في الثاني. افتح التفاصيل وتأكد من ظهور الحساب المرتبط والرسوم إن وجدت.
3. افتح حركة صوتية أو فاتورة معتمدة وتحقق من مصدر التسجيل. المسودات غير المعتمدة لا تُعرض كحركات مالية.
4. تحقق من حركات الادخار والديون، ثم من عملية معكوسة وقيد عكسها دون إخفاء الأصل.
5. جرّب النوع والحالة والفترة والترتيب وحجم الصفحة والتنقل. اختبر حسابًا فارغًا وحسابًا مؤرشفًا كذلك.
6. جرّب «تحديث السجل والرصيد»، والعربية والإنجليزية والوضع الداكن والهاتف، وفتح تفاصيل الحركة باستخدام لوحة المفاتيح.
7. في Network يجب أن تظهر قراءات `GET /api/transactions` بمعامل `account_id` الخاص بالحساب الحالي. زر التحديث يقرأ الحساب كذلك؛ عرض السجل لا ينشئ عملية أو يغير رصيدًا.

## للفريق أو لأي تعديل لاحق بواسطة AI

اقرأ هذا المستند والملفات الحالية قبل تغيير سجل الحساب. حافظ على عقد الباك، مصدر المبالغ من قيود الحساب، دقة المنازل الأربع، ظهور العكس، حدود ملخص الصفحة وإلغاء الطلبات القديمة. لا تخلط هذا التعديل مع إعادة كتابة الحسابات أو التسجيل الصوتي أو القوالب أو منطق دفتر الأستاذ.
