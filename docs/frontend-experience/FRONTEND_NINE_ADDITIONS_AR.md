# SmartSpend — تسليم إضافات تجربة المستخدم التسع

هذا التعديل مبني على نسخة الفرونت المرفقة `Front.zip`، بما فيها التسجيل الصوتي والفواتير الذكية وسجل حركات الحساب. التنفيذ في الفرونت فقط ويستخدم عقود API الموجودة؛ لا يتطلب ملفات باك إند جديدة أو migrations أو تغيير إعدادات Laravel Cloud.

## 1. أين تجد كل إضافة؟

| الإضافة | مكانها | الاستخدام |
|---|---|---|
| سجل عمليات التصنيف | تفاصيل أي تصنيف `/dashboard/categories/:categoryId` | عرض العمليات المرتبطة بالتصنيف، مع التاريخ والحساب والحالة والترتيب والتنقل بين الصفحات. |
| مركز «ما يحتاج انتباهك» | القائمة الجانبية ← نظرة عامة، `/dashboard/attention` | الالتزامات القريبة والمتأخرة، تنبيهات الميزانيات، ومسودات الفواتير والصوت الجاهزة للمراجعة. |
| المراجعة الشهرية | القائمة الجانبية ← التقارير، `/dashboard/reports/monthly-review` | اختر الشهر واتبع خمس خطوات: نظرة عامة، الدخل والمصروف، المقارنة، الميزانيات، والأهداف. |
| كشف حركات الحساب PDF وCSV | تفاصيل الحساب ← «كشف حركات الحساب» | اختر بداية ونهاية الفترة ثم صيغة التنزيل. الكشف يشمل صفحات الفترة كلها. |
| قوالب الإدخال السريع | القائمة الجانبية ← العمليات المالية، `/dashboard/financial-operations/templates` | أنشئ قالباً أو احفظ النموذج اليدوي الحالي كقالب؛ تطبيق القالب يملأ النموذج ويظل الحفظ المالي قراراً صريحاً للمستخدم. |
| الفلاتر المحفوظة | العمليات المالية، التقارير، سجل الحساب، وسجل التصنيف | اضبط الفلاتر ثم احفظ العرض باسم واضح. تستطيع تطبيقه أو حذفه لاحقاً. |
| تخصيص لوحة التحكم | لوحة التحكم ← «تخصيص لوحة التحكم» | إظهار أو إخفاء الأقسام، تغيير ترتيبها بأزرار واضحة، أو استعادة الترتيب الافتراضي. |
| دليل البداية | القائمة الجانبية ← نظرة عامة، `/dashboard/getting-started` | متابعة إنشاء حساب وعملية وميزانية وهدف عبر الأقسام الحالية. يمكن إخفاء بطاقة الدليل ثم إعادتها من الإعدادات. |
| إخفاء المبالغ | زر العين في الشريط العلوي، وكذلك الإعدادات ← التفضيلات | إخفاء عرض المبالغ والرسوم والمحتوى المالي الحر المشمول بالتعديل، وإعادته بضغطة. |

القائمة الجانبية تحتفظ بالأقسام القديمة وتضع الروابط الجديدة بجانب وظائفها المرتبطة. التصميم يستخدم ألوان المنصة وخطوطها الحالية، ويدعم العربية والإنجليزية وRTL والثيم الحالي والشاشات الصغيرة، مع حركة هادئة واحترام إعداد تقليل الحركة.

## 2. تشغيل النسخة محلياً

1. فك الضغط إلى مجلد مستقل. المشروع الكامل موجود داخل `SmartSpendWeb`.
2. انسخ ملف `.env` الذي تعمل به حالياً إلى جذر هذا المجلد، مع إبقاء عنوان الباك إند الحالي. ملف `.env.example` موجود كمرجع، ولا توجد مفاتيح OpenAI جديدة في الفرونت.
3. افتح Terminal داخل مجلد المشروع ثم نفّذ:

```powershell
npm ci
npm run dev
```

4. افتح الرابط الذي يعرضه Vite وسجّل الدخول بالطريقة المعتادة.
5. النسخة تتضمن الكود والأصول والخطوط والاختبارات وملف القفل. تثبيت `node_modules` وإنشاء `dist` يتمان محلياً بالأوامر المذكورة؛ لا يتضمن الأرشيف بيانات Git أو ملف البيئة الفعلي.

متطلب Vite الموجود في المشروع هو Node.js `^20.19.0 || >=22.12.0`. تم الفحص هنا باستخدام Node.js 24.19.0.

إذا كان الفرونت يستخدم `VITE_API_BASE_URL` مباشراً، احتفظ بالقيمة التي كانت تعمل لديك. إعداد proxy الموجود مسبقاً في `vite.config.js` ما زال كما هو؛ وعند استخدام `/api` محلياً يوجّه الطلبات إلى الباك المحدد فيه أو في `SMARTSPEND_DEV_API_ORIGIN`.

## 3. التفاصيل التي تحفظ المنطق

### التفضيلات والقوالب والفلاتر

- الحفظ محلي في متصفح المستخدم، بمفتاح منفصل لكل مستخدم ولكل مساحة عمل: `smartspend:experience:v1:u:<userId>:w:<workspaceId>`.
- لا تُرسل هذه التفضيلات إلى الباك ولا تتزامن تلقائياً بين الأجهزة. التبويبات في المتصفح نفسه تتلقى التحديثات عبر حدث `storage`.
- الحد المحلي 20 قالباً و30 عرضاً محفوظاً. يمكن حذف العناصر من واجهاتها، أو مسح القوالب والعروض من الإعدادات.
- إذا رفض المتصفح التخزين، تظل التفضيلات قابلة للاستخدام خلال الجلسة، وتظهر رسالة تبين أن الحفظ الدائم غير متاح.
- قراءة JSON تالف أو إصدار غير معروف تعيد إعدادات سليمة. لا يوجد مفتاح مشترك للمستخدمين عند غياب هوية المستخدم أو مساحة العمل.
- القالب يحفظ الاسم والنوع والحساب والتصنيف والعملة والمبلغ الاختياري والوصف. المبلغ يظل نصاً عشرياً دقيقاً؛ لا يُحوّل إلى `float`.
- تطبيق القالب يتحقق من الحساب الفعّال في مساحة العمل، العملة، أهلية التصنيف، وعدم كونه حساب هدف ادخار. الحساب المؤرشف أو التصنيف غير النشط لا يطبّقان قالباً قديماً.
- عند التطبيق يُستخدم تاريخ جديد ويُمسح رقم المرجع القديم. لا يحتفظ القالب بتأكيد سابق أو تاريخ قديم أو مفاتيح تنفيذ مالي.
- القالب يملأ نموذج الإدخال اليدوي فقط. لا ينفّذ `POST /transactions` وحده، ولا يلغي التحقق والتأكيد والمفتاح المستقر في التدفق المالي الحالي.
- الفلاتر المحفوظة تخص الصفحة أو الحساب أو التصنيف الذي حفظت فيه. لا تحفظ نوايا إنشاء عملية أو المستخدم أو مساحة العمل أو رقم صفحة قديم؛ وتُراجع عبر قواعد الصفحة عند التطبيق.

### سجل التصنيف

- يقرأ `GET /transactions` عبر `transactionsApi` الموجود، مع تثبيت `category_id` وعدم إضافة عقد API جديد.
- يحافظ على المبالغ الدقيقة والعملة لكل عملية؛ لا يجمع عملات مختلفة في رقم واحد.
- يتيح حالات الباك الحالية: `posted`, `reversed`, `draft`, `pending_review`, `failed`.
- التصنيف الخاص لا يقبل نتائج لمساحة عمل مختلفة. التصنيف العام يعرض ما يسمح به الباك للمستخدم، مع توضيح النطاق.
- نتيجة فارغة تعرض حالة فارغة؛ فشل الطلب يعرض خطأ قابلًا للمحاولة ولا يتحول إلى بيانات صفرية.

### مركز الانتباه

- يقرأ التقويم ضمن 30 يوماً قبل اليوم و30 يوماً بعده، ويستبعد الالتزامات المنتهية وفق حالتها الفعلية. لا يصنع حالة «متأخر» لمجرد مرور تاريخ.
- يعيد استخدام `FinancialAlerts` الحالي؛ هذا المسار يستخدم اسم الفلتر الموجود `id_workspace` كما هو.
- يعرض أول 20 مسودة جاهزة لكل قناة مع رابط للوصول إلى المزيد. نطاق الفواتير يظل النطاق المصرح به في قائمة الفواتير الحالية، ونطاق الصوت مساحة العمل المختارة.
- أقسام الطلبات مستقلة، لذلك فشل قسم لا يخفي الأقسام السليمة. الروابط تفتح التدفقات الحالية، بما فيها فتح المسودة الصوتية دون إعادة رفعها أو استهلاك محاولة جديدة.

### المراجعة الشهرية

- تستخدم تقارير الباك الحالية للملخصات والتحليلات، ولا تستنتج مجموعاً من صفحة جزئية للعمليات.
- المقارنة تقرأ الشهر الحالي والشهر التقويمي السابق فعلياً. مثلاً مارس يقارن بفبراير، لا بفترة متحركة مساوية لعدد أيام مارس.
- الفروق بين مبالغ الشهرين تستخدم أعداداً صحيحة `BigInt` بوحدات عشرية دقيقة، ولكل عملة مجموعة مستقلة. البيانات المفقودة تبقى مفقودة.
- النطاق يطابق صفحة التقارير الحالية ومساحات العمل المصرح بها فيها؛ لم يُغيّر عقد `reportsApi` بإضافة فلتر ملكية جديد.
- إنهاء المراجعة إشارة واجهة خلال الجلسة فقط، ولا يغيّر قيوداً مالية ولا يستدعي OpenAI.

### كشف الحساب

- يقرأ جميع صفحات `GET /transactions` الخاصة بالحساب والفترة، بترتيب زمني و100 نتيجة في الصفحة، ثم يعيد قراءة الصفحات للتحقق من ثباتها.
- يرفض الملف الجزئي عند فشل صفحة أو إلغاء الطلب أو اختلاف النتائج بين القراءتين أو وجود عملية مكررة. يعرض تقدماً وزر إلغاء.
- الحد الأقصى 5000 عملية للكشف الواحد؛ عند تجاوز الحد يُطلب اختيار فترة أقصر، ولا يُنزّل ملفاً مقتطعاً.
- الأثر المالي مأخوذ من `ledger_entries` الخاصة بالحساب، شاملاً رسوم الحساب. لا يُستخدم مبلغ عنوان التحويل بوصفه الأثر على الحساب.
- الوارد والصادر والأثر الصافي يحسبون بدقة أربع منازل عشرية؛ لا ينشأ رصيد افتتاحي أو ختامي تقديري.
- العملية الأصلية والعملية العكسية تبقيان صفين مستقلين. الحساب المؤرشف يمكن عرض كشفه دون تعديل بياناته.
- CSV يدعم العربية عبر UTF-8 BOM، ويحمي الحقول النصية الخارجية من تفسيرها كصيغ جداول. الأرقام المالية تظل قيماً دقيقة.
- PDF جديد مستقل عن PDF التقارير القديم، ويدعم صفحات متعددة وترويسة وعناوين أعمدة وتذييلاً متكرراً. وقت العملية في التصدير موضح بتوقيت UTC.
- إعادة القراءة تكشف التغييرات المشاهدة أثناء الجمع، لكنها لا تنشئ snapshot مقفلاً في قاعدة البيانات. إذا كانت الفترة تتغير باستمرار، جرّب التصدير بعد استقرار الحركات.

### إخفاء المبالغ

- `PrivateMoney` يزيل القيمة من النص المعروض ويستبدلها بعلامة محايدة مع وصف وصول مناسب. يبقي الأعداد غير المالية مثل عدد العمليات ظاهرة.
- يشمل المواضع المالية المعدلة في لوحة التحكم والحسابات والعمليات والتحويلات والميزانيات والأهداف والديون والمتكرر والتقارير والاستيراد والفواتير والصوت والتنبيهات والمساعد.
- الرسوم المالية تخفى من العرض عند تفعيل الخيار. لا تُعاد تهيئة صفحة العمليات أو تدفق الصوت عند تبديل الخصوصية، حتى لا تضيع محاولة أو عملية معلقة.
- حقول الإدخال والمراجعة تبقى قابلة لرؤية القيم وتحريرها لاتخاذ قرار مالي صحيح. خيار الإخفاء هو تفضيل للعرض، وليس تشفيراً للبيانات أو إزالة لها من الذاكرة أو الشبكة.
- يمنع تصدير كشف الحساب الجديد أثناء الإخفاء، ويلغي جمعه الجاري عند تفعيل الخيار. قوالب التقارير القديمة ووظيفة تصديرها بقيتا كما هما.
- الأسماء والأوصاف الشخصية الحرة قد تحتوي أرقاماً؛ لا يُفسّر الخيار باعتباره إخفاءً لكل رقم في كل نص يكتبه المستخدم.

## 6. تجربة عملية قبل النشر

1. افتح لوحة التحكم، أخفِ قسماً وغيّر ترتيب قسمين. حدّث الصفحة وتأكد من بقاء الاختيار، ثم استعد الافتراضي.
2. فعّل زر العين. تحقق من الحسابات والتقارير والأهداف والرسوم، ثم افتح نموذجاً يدوياً وتأكد أن حقوله لا تزال قابلة للمراجعة والتحرير.
3. أنشئ قالب مصروف بمبلغ ذي أربع منازل عشرية. افتحه وطبّقه في النموذج، وتأكد أن رقم المرجع فارغ والتاريخ جديد وأن العملية لا تُحفظ قبل ضغط التأكيد الحالي.
4. أرشف حساباً يخص قالباً قديماً، ثم افتح القالب وتأكد من منع تطبيقه حتى اختيار حساب فعّال مناسب.
5. احفظ فلاتر في العمليات والتقارير وسجل الحساب والتصنيف، ثم غيّرها وطبّق العرض المحفوظ. تحقق من أن عرض حساب آخر لا يظهر ضمن هذا الحساب.
6. افتح تصنيفاً ذا عمليات، وجرب الفلاتر والصفحات وروابط تفاصيل العمليات. جرّب تصنيفاً بلا عمليات أيضاً.
7. افتح مركز الانتباه، وافتح مسودة صوت جاهزة منه. تأكد أن فتحها يستعمل طلب قراءة ولا يبدأ تحليلاً جديداً، ثم جرّب التنقل الطبيعي للصوت والفواتير والإدخال اليدوي.
8. جرّب المراجعة الشهرية لشهرين بأطوال مختلفة، وقارن الأرقام بالتقارير الحالية، بما فيها مجموعات العملات المنفصلة.
9. نزّل كشف حساب بفترة تتجاوز صفحة واحدة، بصيغتي PDF وCSV. قارن أرقام الحركات وأثرها، وجرب التحويلات ذات الرسوم والعمليات المعكوسة والحساب المؤرشف.
10. جرّب مستخدمين أو مساحتي عمل مختلفتين، وتأكد من فصل التفضيلات والقوالب والعروض. جرّب العربية والإنجليزية والثيمين وشاشة الهاتف والتنقل بلوحة المفاتيح.
11. افتح دليل البداية وتأكد من توافق حالاته مع بيانات المستخدم، ثم أخفِ بطاقته وأعدها من الإعدادات.

node --test tests/*.test.mjs
npm run lint
